## 🌱 آرا چیست

آرا یک برنامه‌ی **مدیریت مالی شخصی** برای اندروید است که تمام پردازش و نگه‌داری داده را روی خود دستگاه انجام می‌دهد. نه حساب کاربری می‌خواهد، نه ثبت‌نام، نه اتصال به اینترنت — چون اصلاً سروری در کار نیست.

طراحی رابط کاربری از پایه برای فارسی و چیدمان راست‌به‌چپ انجام شده: اعداد فارسی، تقویم هجری شمسی، و متنی که به زبان روزمره نوشته شده، نه ترجمه‌ی تحت‌اللفظی.

> **💡 اصل بنیادین:** موجودی هیچ‌وقت به‌عنوان یک عدد ذخیره نمی‌شود. همیشه از روی تراکنش‌های تأییدشده محاسبه می‌شود. این یعنی هیچ مسیری وجود ندارد که موجودی با واقعیت اختلاف پیدا کند.

## ✨ امکانات

### 🤖 تشخیص خودکار تراکنش

آرا پیامک و اعلان بانک را می‌خواند و تراکنش را با مبلغ، تاریخ، طرف حساب و دسته‌ی پیشنهادی می‌سازد.

موتور تشخیص، **ساختار پیام را امتیاز می‌دهد، نه الگوی حفظ‌شده را**. برای همین وقتی بانکی قالب پیامکش را عوض کند یا بانک تازه‌ای اضافه شود، همچنان کار می‌کند — بدون به‌روزرسانی برنامه.

کیفیتش حدس و گمان نیست: روی مجموعه‌ای از ۶۴ پیام واقعی و تعمیم‌یافته به‌علاوه‌ی ۸۹ پیام منفی (تبلیغات، کد تأیید، پیام‌های غیرمالی) سنجیده می‌شود و تستِ کیفیت اگر از این آستانه‌ها پایین‌تر بیفتد، شکست می‌خورد:

| سنجه | آستانه |
|:--|:--|
| دقت (Precision) | ≥ ۹۸٪ |
| پوشش (Recall) | ≥ ۹۰٪ |
| F1 | ≥ ۹۴٪ |

**دقت از پوشش مهم‌تر است**؛ یک تراکنش اشتباه در فهرست، اعتماد کاربر به کل برنامه را از بین می‌برد، در حالی که یک تراکنش جامانده فقط یک بار ثبت دستی می‌خواهد.

### 🛡️ صف بازبینی

هیچ تراکنش تشخیص‌داده‌شده‌ای مستقیم وارد موجودی نمی‌شود. همه اول در صف بازبینی می‌نشینند تا خودت تأیید کنی. دکمه‌ی «تأیید همه» هم فقط ردیف‌هایی را لمس می‌کند که موتور به آن‌ها **اطمینان بالا** داده است.

### 📊 تحلیل

نمودار درآمد و هزینه، سهم هر دسته، و مقایسه‌ی دوره‌ای. همه‌ی تحلیل‌ها **قاعده‌محورند** — بدون یادگیری ماشین، بدون ارسال داده به بیرون، و قابل توضیح: هر عددی که می‌بینی می‌توانی بفهمی از کجا آمده.

بینش‌ها کنار میانگین، **خرج یک روز معمولی** را هم می‌گویند. تفاوتشان مهم است: اجاره و قسط در یک روز می‌افتند و میانگین را می‌کشند بالا، پس عددی می‌سازند که هیچ روزی شبیهش نیست.

| | |
|:--|:--|
| **دوام موجودی** | با این روند خرج، پولت تا چند روز دیگر دوام می‌آورد |
| **روز معمولی** | خرج یک روز عادی، جدا از میانگینی که اجاره بالا بُرده |
| **خرج‌های ریز** | مجموع تراکنش‌های کوچکی که به چشم نمی‌آیند |
| **مقایسه‌ی ماه‌ها** | این ماه چقدر شبیه ماه‌های قبل بوده |

### 🧠 الگوی خرج و درآمد

آرا بعد از **یک هفته** شروع می‌کند به گفتن اینکه چطور خرج می‌کنی، و هرچه داده بیشتر شود عمیق‌تر می‌شود. هر پله فقط چیزی می‌گوید که داده‌اش را دارد و صریح می‌گوید بر چه پایه‌ای حرف می‌زند:

| عمق داده | شرط | چه چیزی گفته می‌شود |
|:--|:--|:--|
| در حال شناخت | < ۷ روز | هیچ ادعایی |
| هفتگی | ۷ روز | روز هفته، ساعت خرج، خرج‌های ریز |
| ماه ناقص | نصب وسط ماه | تحلیل، با ذکر تعداد روز |
| ماهانه | ۱ ماه کامل | ریتم ماه اضافه می‌شود |
| پایدار | ۳ ماه کامل | نوسان و خرج‌های تکرارشونده |

به‌جای یک برچسب، **یازده صفت** که هرکدام شدتی از ۰ تا ۱۰۰ می‌گیرند و جفت‌جفت‌اند تا هیچ‌کدام «حالت غلط» به‌نظر نرسد: زودخرج ↔ آخرماه‌خرج، جیب سوراخ ↔ یک‌ضربی، آخرهفته‌ای ↔ وسط‌هفته‌ای، موج‌سوار ↔ حساب‌کتابی، به‌علاوه‌ی شب‌خرج و اشتراک‌باز. تیتر نهایی ترکیب دو صفت قوی است، چون ترکیب است که برای هر نفر یکتا می‌شود.

**درآمد هم الگو دارد.** ریتم رسیدن پول — یک حقوق ثابت یا چند واریز پراکنده، حدوداً چه روزی از ماه، و چقدر ماه‌به‌ماه نوسان دارد. این تفاوت کل استراتژی بودجه‌بندی را عوض می‌کند: یکی می‌تواند اول ماه تقسیم کند، دیگری به ذخیره‌ی ضربه‌گیر نیاز دارد.

### 🎯 بودجه و هدف

برای هر دسته سقف ماهانه بگذار تا پیش از تمام‌شدن پول خبردار شوی. برای خریدهای بزرگ هدف پس‌انداز بساز و پیشرفتش را دنبال کن.

### 👥 دنگ

خرج گروهی — سفر، شام، خانه‌ی مشترک — را بین افراد تقسیم کن. آرا حساب می‌کند چه کسی به چه کسی چقدر بدهکار است و **کمترین تعداد جابه‌جایی پول** برای تسویه‌ی کامل را پیشنهاد می‌دهد.

### 📅 تعهدها

قسط وام، اجاره، قبض و بدهی شخصی را ثبت کن. یادآوری می‌تواند اعلان ساده باشد یا **زنگ تمام‌صفحه** برای سررسیدهایی که نباید از دست بروند.

### 📥 ورود از فایل

صورت‌حساب بانکت را به‌صورت Excel (<span dir="ltr"><code>.xlsx</code></span>) یا CSV بده. آرا خودش سرِ جدول را پیدا می‌کند، ستون‌ها را تشخیص می‌دهد و پیش از ثبت، پیش‌نمایش می‌دهد.

خواننده‌ی <span dir="ltr"><code>.xlsx</code></span> **از صفر نوشته شده و به هیچ کتابخانه‌ی بیرونی وابسته نیست** — نه Apache POI و نه چیز دیگری. یک فایل اکسل در واقع یک ZIP از چند XML است و اندروید هر دو را بومی دارد؛ نتیجه چند مگابایت حجم کمتر و یک وابستگی کمتر برای نگه‌داری.

### دو نسخه، دو سطح دسترسی

پروژه دو flavor دارد و تفاوتشان فقط در مجوزها نیست؛ در خود قابلیت‌هاست:

| | `localMarket` | `googlePlay` |
|:--|:--|:--|
| بازار هدف | کافه‌بازار، مایکت، نصب مستقیم | Google Play |
| خواندن پیامک بانک | ✅ | ❌ |
| خواندن اعلان بانک | ✅ | ❌ |
| مجوز `INTERNET` | ✅ (فقط بررسی به‌روزرسانی) | ❌ |
| ثبت دستی و ورود از فایل | ✅ | ✅ |

نسخه‌ی گوگل‌پلی عمداً محدود است، چون سیاست Google Play اجازه‌ی دسترسی به پیامک را برای این دسته از برنامه‌ها نمی‌دهد.

## 🏗️ معماری

معماری تمیز (Clean Architecture) با الگوی MVVM، در یک ماژول واحد و لایه‌بندی مشخص:

```
com.jibi.finance
├── core/          مدل دامنه، تم و اجزای مشترک رابط کاربری، ابزارها
├── data/          Room، مخزن‌ها (Repository)، پشتیبان‌گیری، ورود از فایل
├── engine/        موتور تشخیص و دسته‌بندی — بدون وابستگی به اندروید
├── features/      هر صفحه: presentation + ViewModel
├── services/      پیامک، شنونده‌ی اعلان، زمان‌بند یادآوری
└── di/            ماژول‌های Hilt
```

`engine/` عمداً از فریم‌ورک اندروید جداست: کد خالص Kotlin که با تست‌های JVM سنجیده می‌شود، بدون شبیه‌ساز و بدون Robolectric.

### پشته‌ی فنی

| لایه | ابزار |
|:--|:--|
| زبان | Kotlin 2.0 |
| رابط کاربری | Jetpack Compose · Material 3 |
| معماری | Clean Architecture · MVVM · Coroutines + Flow |
| تزریق وابستگی | Hilt 2.60 |
| پایگاه‌داده | Room 2.7 روی SQLCipher 4.5 |
| تنظیمات | DataStore |
| احراز هویت | AndroidX Biometric |
| ساخت | AGP 9 · Gradle 9 · KSP · R8 |

## 🔨 ساخت پروژه

```bash
git clone https://github.com/erfan-8/ara.git
cd ara
./gradlew assembleGooglePlayDebug assembleLocalMarketDebug
```

اجرای تست‌ها:

```bash
./gradlew testGooglePlayDebugUnitTest
```

برای ساخت نسخه‌ی امضاشده، این چهار خط را در `local.properties` بگذار (این فایل در <span dir="ltr"><code>.gitignore</code></span> است و هرگز وارد مخزن نمی‌شود):

```properties
releaseStoreFile=/path/to/ara-release.jks
releaseStorePassword=…
releaseKeyAlias=…
releaseKeyPassword=…
```

اگر این مقادیر تنظیم نشده باشند، ساخت نمی‌شکند — خروجی فقط <span dir="ltr"><code>-unsigned</code></span> می‌ماند تا هر کسی بتواند پروژه را بدون کلید انتشار build کند.
